## 背景

在 SESSION-001 基础上，**架构从"本地多角色"演进为完整 C/S 架构**。服务端负责世界持续演进，客户端仅作为"视角"接入。

---

## 核心架构转变

| 维度 | SESSION-001 | SESSION-002 |
|---|---|---|
| 整体架构 | 本地多角色（共享 SQLite） | **C/S 架构**（服务端持续运行 + 客户端连接） |
| 客户端 | 直接读 SQLite | WebSocket 连接服务端 |
| NPC 心意 | 未明确定义 | **玩家不可见 NPC 内心独白** |
| 角色间信息 | 默认可见 | **默认完全不可见**（需探查技能） |
| 知识模型 | 无 | **衰减记忆**（重要知识永久，琐事衰减） |

---

## 新增决策

### C/S 架构

- **服务端**：24/7 持续运行，推进世界、生成事件、过滤可见性、推送视图
- **客户端**：TUI 和 Web 都是"视角"，只显示自己角色可见的信息
- **多客户端共享同一服务器**：世界真相只存在于服务端

### 传输协议

| 决策 | 选择 | 理由 |
|---|---|---|
| 通信协议 | **WebSocket**（`ws` 库） | 实时双向，延迟低 |
| Web 框架 | **Express** | 成熟，TypeScript 支持好 |
| 认证 | **账号密码**（bcrypt 哈希） | 本地自管账号 |

### 可见性系统（核心新增）

#### 信息分层

| 层级 | 类别 | 实现 |
|---|---|---|
| L0 | 角色自身 | 直接读角色状态 |
| L1 | 同空间 | 房间距离过滤 |
| L2 | 邻近听觉 | 距离+强度 |
| L3 | 知识库 | per-character knownBy |
| L4 | 剧情触发 | plot flag 匹配 |
| L5 | 服务端私有 | 不外泄 |

#### 角色间信息可见性

- **默认完全不可见**：玩家-玩家 / 玩家-NPC / NPC-NPC 都默认只能看到名字/外观/行为
- **不可见 NPC 心意**：玩家只见 NPC 言行，NPC 决定如何传递信息
- **探查技能**：唯一可获取对方属性的途径
  - 探查者等级 >= 目标等级才可使用
  - 技能等级 + 熟练度决定信息范围
  - 一次快照（**冻结**，不响应目标后续变化）

#### 知识衰减

- 每个 knowledge entry 有 relevance 分数
- 每个 tick 后自动衰减
- relevance 低于阈值 → 遗忘
- permanent 标记的知识不衰减
- 复述/重提可强化 relevance

## 事件过滤管线

```
WorldEvent (完整真相)
   ↓
spatialFilter (空间规则)
   ↓
knowledgeFilter (知识规则)
   ↓
plotFilter (剧情规则)
   ↓
decayFilter (时间衰减)
   ↓
LLM Narrator (视角叙事)
   ↓
CharacterView → WebSocket 推送
```

每个连接客户端独立过滤，**严格保证信息不外泄**。
